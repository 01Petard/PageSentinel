# 开发阶段与验收

## 1. P0：最小技术验证

先不做业务 UI，验证最容易造成误报的执行链路。

- 使用 Playwright 访问受控静态页面、动态加载页面和列表页面。
- 实现 TEXT / LIST 提取、标准化、文本比较和历史 Key 去重。
- 验证稳定等待、匹配数量、空结果、重复链接和结果上限。

阶段验收：文本修改和新增条目能被识别，重排与旧条目回归不误报。

## 2. P1：规则管理与基础交互

- 搭建 Vue、Fastify 和最小 SQLite 存储。
- 实现任务列表、任务详情、规则编辑抽屉。
- 完成规则测试、创建、编辑、暂停、删除和手动检查。
- 清楚展示提取预览、匹配错误和最近执行结果。

阶段验收：通过 Web 界面创建规则，真实采集页面，并查看保存后的任务与检查结果。测试规则不改变正式基线。

## 3. P2：自动执行与变化历史

- 完善快照、历史已见条目、检查记录和变化事件持久化。
- 实现进程内调度、并发限制、任务互斥、失败退避和重启恢复。
- 展示 TEXT 差异、LIST 新增条目和历史时间线。
- 落实修改规则重建基线、异常不推进基线。

阶段验收：关闭前端页面后持续检查；服务重启保留任务、基线和历史去重状态。

## 4. P3：通知、部署与回归

- 接入单个 ntfy 目标，处理待发状态、失败重试和重启恢复。
- 完成本地启动和单容器部署，挂载 SQLite 持久化目录。
- 验证浏览器 Context 释放、任务退出清理和部署访问边界。
- 执行下面六组回归场景。

阶段验收：有效变化产生一次变更事件并触发通知；异常不破坏历史状态。通知采用至少一次投递，允许崩溃窗口内重复推送。

## 5. 六组必测场景

以下六组已在受控环境验证，证据见 [实施与验收记录](../开发进度.md)。个人 ntfy 主题实际投递与一个月长期试运行仍需部署后验证。

| 状态 | 场景 | 验收条件 |
| --- | --- | --- |
| [x] | 首次采集与测试隔离 | 首次有效采集仅建基线；规则测试不改变已保存任务、基线和已见集合 |
| [x] | TEXT 正常变化与去噪 | 实质文本修改产生可读 Diff；标准化空白和已排除子元素变化不通知 |
| [x] | LIST 历史去重 | 新条目只生成一次新增事件；重排、暂时消失后回归不重复通知 |
| [x] | 失败保护与恢复 | 超时、403 / 429、选择器失效、空列表不推进基线；恢复后仍与最后成功状态比较 |
| [x] | 调度与规则编辑 | 手动和自动执行不重叠；暂停停止后续自动调度；关键规则修改重建基线，名称或间隔修改保留基线 |
| [x] | 重启和通知恢复 | 重启后保留任务、基线和历史 Key；待发通知继续处理，推送失败不回滚已保存变化 |

补充边界检查：TEXT 多匹配、LIST 缺链接或重复 Key、超过结果上限时明确报错，不静默降级或截断。

## 6. 测试数据与长期试运行

自建三个受控页面：静态正文页、延迟加载 SPA、可新增和重排的列表页。用固定数据复现变化、重排和失败，避免把第三方网站的波动当作唯一验收依据。

MVP 通过后，用少量真实公开页面持续试运行，观察漏报、误报、失败恢复和资源使用。长期目标是稳定运行一个月，准确保留变化证据并发送通知。

## 7. 首版后再考虑

| 顺序 | 能力 | 技术价值 |
| --- | --- | --- |
| 1 | 可视化元素选择器 | 页面预览、坐标映射、DOM 定位、选择器稳定性 |
| 2 | 视觉差异监控 | 一致视口、动态遮罩、像素差异和误报过滤 |
| 3 | 结构化字段监控 | 价格和库存等字段、类型转换、阈值规则、结构化 Diff |

上述能力均不属于 v0.1。完成首版后根据实际使用问题选择下一项。
