# 产品定位与 MVP

## 1. 产品定位

PageSentinel / 页面哨兵  
Track what matters. —— 只追踪真正关心的网页变化。

面向个人开发者和有定期查阅需求的用户，提供公开网页的持续监控。产品价值集中在自部署、透明的提取规则、结构化新增检测和可解释的变化记录。

| 目标页面 | 用户关心的变化 | 首版模式 |
| --- | --- | --- |
| 软件更新日志 | 版本和更新说明是否修改 | TEXT |
| 商品详情区域 | 选中的价格文本是否变化 | TEXT |
| 博客、新闻、公告列表 | 是否出现新文章、新公告 | LIST |
| 招聘页面 | 是否出现新职位 | LIST |
| 指定搜索结果页 | 当前页面是否出现历史未见条目 | LIST |

项目的技术投入集中于浏览器采样、内容提取、去噪去重和状态可靠性。UI 用于配置任务和查阅证据。

## 2. 两种监控模式

| 模式 | 提取结果 | 比较依据 | 通知条件 |
| --- | --- | --- | --- |
| TEXT | 唯一选中区域的可见文本 | 标准化文本与上次成功基线 | 文本内容发生变化 |
| LIST | 列表项的标题、详情链接、唯一 Key | 当前 Key 与任务历史已见 Key 集合 | 出现历史未见 Key |

TEXT 支持排除监控区域内的指定子元素，例如动态更新时间。LIST 仅检测新增，不通知删除和重排，不追踪同一链接对应条目的标题修改。

## 3. MVP 功能清单

| 功能 | 首版要求 |
| --- | --- |
| 创建与编辑 | 名称、HTTP(S) URL、模式、CSS 选择器、检查间隔及必要提取配置 |
| 测试规则 | 真实采集并预览文本或列表；不保存快照、不改变基线 |
| 首次采集 | 保存后立即检查，首次有效采集只建立基线 |
| 自动检查 | 服务端定时执行，关闭前端页面后继续工作 |
| 手动检查 | 使用与自动检查相同的正式处理流程 |
| 变化历史 | TEXT 前后差异；LIST 本次新增条目 |
| 执行记录 | 时间、结果、耗时、失败原因 |
| 通知 | 使用 ntfy 单渠道推送，持久化待发送状态 |
| 任务管理 | 启用、暂停、编辑、删除 |
| 持久化与部署 | SQLite、本地运行、单容器部署、重启恢复 |

默认间隔建议 30 分钟，可选 15、30、60、180 分钟。目标规模为 5—20 个任务。

## 4. 页面与交互

仅保留两个主页面。

| 页面或操作 | 展示与交互 |
| --- | --- |
| 监控列表 | 名称、运行状态、最近结果、最近变化、下一次检查时间；提供暂停和立即检查 |
| 监控详情 | 规则摘要、变化时间线、TEXT 差异或 LIST 新增条目、执行记录、原网页链接 |
| 新建与编辑 | 右侧抽屉；规则输入与测试预览放在同一处 |
| 查看变化 | 进入详情页 |
| 删除任务 | 确认弹窗 |
| 检查失败 | 在详情页说明原因 |

完整操作顺序：输入 URL → 配置规则 → 测试提取 → 保存并建立基线 → 后台检查 → 收到通知 → 查看变化证据。

## 5. 首版不做

- 账号体系、多用户、团队协作、订阅收费。
- 登录态、Cookie 导入、验证码处理、反爬绕过。
- 任意 JavaScript 执行编辑器、复杂 XPath、流程编排。
- AI 语义变化判断、整页像素差异。
- 全站爬取、自动分页、跨页面追踪。
- 浏览器扩展、macOS DMG、手机 App。
- KPI 仪表盘、趋势分析、多通知平台管理。

完成 v0.1 闭环前保持以上边界。
