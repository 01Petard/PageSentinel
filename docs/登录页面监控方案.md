# 登录页面监控：凭证与会话方案

本次结论：可以沿用现有 Chromium 采集链路，优先让用户完成一次交互登录，再复用登录态。当前版本仍只支持无需登录的公开网页；本次未加入凭证录入、导入或自动登录功能。

## 建议的用户流程

1. 用户创建“登录身份”，选择站点。使用专用浏览器窗口完成登录，包括扫码、短信、MFA；不要求把账号密码交给 PageSentinel。
2. 登录成功后保存该身份的浏览器状态，监控任务只引用身份 ID。每次采集创建隔离的 BrowserContext 并加载该状态，避免不同账号互相污染。
3. 先测试监控规则，确认拿到的是登录后的目标内容，再建立基线。
4. 会话失效时显示“需要重新登录”，保留原基线、停止该身份的自动采集并提醒用户更新登录态。不能把登录页文本当成页面变化或新基线。

Playwright 的 `storageState()` 支持保存 Cookie 与 localStorage；需要 IndexedDB 时显式使用 `storageState({ indexedDB: true })`，在 `browser.newContext({ storageState })` 中恢复。sessionStorage 需要单独按域保存与注入，不能假设其会自动恢复。[官方认证说明](https://playwright.dev/docs/auth)、[BrowserContext API](https://playwright.dev/docs/api/class-browsercontext#browser-context-storage-state)。

## 凭证来源的取舍

| 方案 | 适用情况 | 难点 |
| --- | --- | --- |
| 用户在专用窗口登录后保存状态（优先） | Cookie、SSO、扫码和 MFA 网站 | 部署在 Docker/远程服务器时，需要本地辅助程序导出状态，或受控远程登录窗口；用户自己的浏览器 Cookie 不会自动进入服务器 |
| 用户导入 Cookie / storageState | 用户熟悉浏览器工具，能接受手动更新 | Cookie 单独导入不足以覆盖 localStorage、IndexedDB 登录；过期或绑定设备/IP 的会话可能无法迁移 |
| API Token / HTTP Basic | 站点明确提供官方接口或标准鉴权 | Token 应按站点绑定，禁止给所有资源请求注入全局 Authorization |
| 保存账号密码后自动填表 | 登录流程简单且没有交互验证 | 表单变化、验证码、MFA、风控与密码保管成本高，不作为默认路径 |

Web 前端受同源策略限制，也无法直接读取 HttpOnly Cookie；不能在 PageSentinel 页面中自动提取其他站点的完整登录凭证。[HttpOnly 说明](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie#httponly)。

## 实现时必须覆盖的边界

- 登录身份按账号与站点隔离；允许的目标域和登录跳转域显式配置。保持现有公共地址校验、Docker 出口限制和 Chromium 沙箱，不为登录开放任意内网访问。
- 存储状态与密码一样敏感：后端加密持久化，主密钥放在数据库之外；接口只返回身份名称、站点、状态和更新时间，日志、错误、Git 与浏览器 localStorage 均不返回原始凭证。支持撤销与删除。
- 当前工具本身无应用鉴权。加入真实身份管理前，应先保护管理入口，并对缩略图、快照和备份设置访问控制；登录后内容可能包含私人数据。
- 失效识别结合 401/403、登录跳转和用户配置的“已登录标记”。HTTP 200 不代表仍然登录；通用规则无法可靠识别所有站点，必须有站点级测试。
- 会话可能绑定浏览器、设备、IP 或服务端策略。需要在实际部署网络中验证；MFA/验证码由用户完成，无法承诺永不过期或全站通用。
- 若网站会轮换会话 Cookie，成功检查后应受控更新登录态；同一身份的状态写入需串行，避免旧状态覆盖新状态。

## 本次技术验证

在本机 macOS 上使用项目已安装的 Playwright / Chromium 和一次性本地站点，验证了：匿名访问返回 401 → 登录取得 HttpOnly Cookie → 保存 storageState → 新建隔离上下文恢复后返回 200、读到目标正文 → 服务端令会话失效后再次返回 401。状态仅保存在内存，未保存用户凭证。

这证明基础的登录态复用路线可行；不是对具体第三方网站的登录、SSO、MFA或风控兼容性验收。建议下一阶段先选择一个真实目标站点，实现“身份管理 + 手动登录/导入 + 失效提醒”，再按站点扩展。
