# v0.2 设计：需要登录的网页监控

状态：**待维护者评审，未开始功能开发**。本文件中的模型、接口、配置和命令均为拟定契约，当前 v0.1 不提供这些能力。实施顺序见 [v0.2 实施计划](v0.2-PLAN.md)。

## 1. 目标与边界

用户提供一次可用的登录态，PageSentinel 在服务端复用它采集目标页面；登录过期时保留原内容与基线，提示重新登录。公开网页继续按 v0.1 工作。

必须同时交付两种来源：

| 来源                       | 用户操作                                                            | 适用部署                                                        |
| -------------------------- | ------------------------------------------------------------------- | --------------------------------------------------------------- |
| 专用窗口登录               | 本机助手打开独立 Chromium；用户完成登录、扫码或 MFA；确认后保存状态 | 本地 Node、当前本机 Docker；远程服务需 HTTPS 配对并做部署端验证 |
| Cookie / storageState 导入 | 在网页粘贴或上传状态，验证通过后保存                                | Docker / Node 均可，无桌面环境的服务器也可用                    |

本版本不保存账号密码、不自动填表、不代答验证码、不绕过风控；不读取用户日常浏览器的配置目录。只访问公开网络中的登录页面，现有私网限制继续有效。sessionStorage、原生 Passkey 私钥迁移、客户端证书、OPFS、设备绑定会话不在首轮兼容承诺中；依赖这些能力的站点必须明确报告不兼容。

## 2. 产品流程

增加“登录身份”管理入口，沿用当前紫色 / 青柠视觉和抽屉交互，不增加账号体系或团队功能。任务编辑器可选“不使用登录身份”或已验证身份，并显示目标域是否匹配。

身份只展示名称、适用域、获取方式、状态、最后验证时间、关联任务数量；任何列表 / 详情 / 错误响应不返回原始 Cookie、Token 或 storageState。原始导入内容仅在用户输入的当前表单内短暂存在，关闭或提交后清除，不写浏览器持久化存储。

改名直接保存。修改授权域或验证规则时，以候选配置和当前状态重新验证；通过后才更新 revision 并重新加密，失败保留原配置与凭证。

### A. 专用窗口登录

1. 创建身份，配置登录 URL、验证 URL、登录成功标记 CSS、允许的目标及 SSO 域。
2. 点击“在专用窗口登录”。页面创建一次性采集会话，显示可复制的本地助手命令和剩余有效期。
3. 用户在 Mac 上运行命令，助手打开新的有界面 Chromium。Cookie 与网站交互留在该窗口，不混用日常浏览器身份；账号密码、扫码与 MFA 由用户操作。
4. 用户回到 PageSentinel 点击“保存登录状态”；助手响应保存请求，采集允许范围内的状态并上传。关闭窗口、取消或超时均不保存。
5. **服务端运行环境**新建隔离 Context 验证目标 URL 和成功标记。验证通过后才加密保存，并允许任务绑定；验证失败不替换原有可用身份。

当前 Docker 只装 headless shell，没有显示服务器。因此采用“本机助手 + 一次性配对”，不在容器内假装弹窗，也不引入 VNC / 远程桌面。助手由仓库提供拟新增的 `npm run auth:login -- --server <地址>`；需要宿主机 Node 和完整 Chromium，作为此方式的额外依赖。首次在终端交互输入配对码，**配对码不作为命令行参数**，不把管理员 Token 写进命令历史。

配对码为 32 字节随机值，仅创建时返回，服务端保存摘要；有效期 10 分钟，成功配对即消费，并换取有效期不超过原会话的限权助手令牌。令牌仅允许一个身份的一次状态提交，失败或成功提交后均失效，重试需重新配对。会话保存在内存，重启即取消；每个身份最多一个采集会话，全局最多两个。助手只获该会话的轮询、提交、取消权限，不能读取任何已有凭证或任务数据。服务地址仅允许 loopback HTTP 或 HTTPS。

保存过程拟采用 `WAITING_HELPER → LOGGING_IN → SAVE_REQUESTED → VERIFYING → COMPLETED`；任一步可进入 `CANCELLED / EXPIRED / FAILED`。助手每 2 秒轮询，连续 30 秒无法联系服务端、超时和退出均关闭浏览器；服务端不得无人确认即自动提交。

### B. 导入 Cookie / storageState

1. 创建或选择身份，确认目标域和验证规则。
2. 选择 Cookie 或 storageState，粘贴内容或上传文件。保存前显示域、条数、过期项等脱敏摘要，不回显凭证值。
3. 规范化、校验范围，在服务端验证；通过后原子保存，失败保持旧身份和任务状态。

首轮格式固定为：Playwright Cookie JSON 数组、`Cookie: a=b; c=d` 请求头文本、标准 storageState JSON。请求头不包含域 / Path / 过期时间等属性，必须明确使用验证 URL 的精确主机、`/` 路径和会话 Cookie；不猜测父域。JSON 支持原有 HttpOnly、Secure、SameSite、秒级 expires；不把毫秒误当秒。Netscape cookies.txt 不在首轮格式中，界面提示转换为 JSON，不能误判为请求头。

storageState 允许 `cookies`、`origins.localStorage` 和 IndexedDB；不接受混入不支持的私钥 / OPFS 字段。最大 HTTP 请求体与有效状态均为 2 MiB，最多 500 个 Cookie，最多 20 个批准主机；只在导入和助手提交路由放宽当前 64 KiB bodyLimit，其他接口保持原限制。

## 3. 登录身份与任务绑定

身份状态为 `EMPTY / READY / NEEDS_LOGIN`。验证中的状态放在临时操作会话，不提前将待验证数据写成 READY。

| 操作                           | 基线与已见集合                         | 自动检查                                       |
| ------------------------------ | -------------------------------------- | ---------------------------------------------- |
| 老任务无身份                   | 沿用原行为                             | 沿用独立 enabled                               |
| 新增 / 改变 / 解除任务身份绑定 | 清空当前基线和 LIST 已见集合，历史保留 | 首次成功重新建基线，不通知变化                 |
| 同一账号重新授权               | 保留上次成功基线                       | 验证后解除登录阻塞；仅 enabled=true 的任务恢复 |
| 切换账号                       | 关联任务重建基线，旧历史保留           | 首次只建基线                                   |
| 自动轮换 Cookie                | 保留基线                               | 继续调度                                       |
| 清除登录态                     | 保留基线、内容与历史，身份变 EMPTY     | 关联任务进入登录阻塞，手动也不能匿名降级       |
| 删除身份                       | 有关联任务时返回 409，先显式解除绑定   | 不自动解绑或匿名继续                           |

人工替换已有身份时，表单必须选择“同一账号更新”或“切换账号”；服务端不通过 Cookie 猜测账号。原有事件记录不改写，账号切换时间进入执行记录，前端区分新旧授权阶段。

`enabled` 仍只代表用户开关。登录阻塞单独保存，不自动把 enabled 改成 false；重新授权也不打开用户已暂停的任务。强制刷新全部必须报告被登录阻塞的任务，不能悄悄跳过或清空结果。

## 4. 采集、验证与失效

每次预览、验证或正式检查都创建独立非持久化 Context，按绑定身份加载状态；每个身份的使用串行，不同身份和公开任务继续共享原全局并发限制。身份锁先于全局采集槽获取，不能让等待同一身份的任务占满全部槽位。

身份有验证 URL、成功 CSS 和可选登录 URL 前缀；任务可覆写成功 CSS，以适应不同页面布局。只有最终 URL 在批准范围、导航成功、成功标记可见且唯一时，才进入原有提取与比较流程。登录标记不同于提取选择器，必须分别验证。

| 信号                         | 处理                                                                                                   |
| ---------------------------- | ------------------------------------------------------------------------------------------------------ |
| 明确 401、命中已配置登录跳转 | 当前任务 `AUTH_REQUIRED`，保留基线并阻塞；再验证身份统一验证 URL，确认也未登录才将身份标记 NEEDS_LOGIN |
| HTTP 200 但缺成功标记        | 当前任务 `AUTH_UNVERIFIED`，阻塞并要求检查规则 / 重新验证，不把登录页写入快照                          |
| 单页面 403                   | `ACCESS_DENIED`，按采集失败处理；不能仅凭 403 判定所有关联任务登录过期                                 |
| 成功标记存在但提取区域失效   | 原提取失败，保留基线；不误标整份身份过期                                                               |
| 验证 URL 超时或 5xx          | 验证失败，不替换旧凭证，不直接判定账号过期                                                             |
| 身份已撤销、缺密钥或域不匹配 | 明确阻止采集，不回退匿名请求                                                                           |

首次进入登录阻塞时记录执行结果并提醒一次；调度不反复采集被阻塞任务，重复手动尝试不重复制造通知。身份验证成功后解除对应阻塞，再与最后成功基线比较；没有成功基线则建立基线。单页面成功标记仍失配时保持该任务阻塞。

鉴权结果写入执行记录和独立阻塞字段，任务 `lastStatus` 保留原采集结果，UI 优先显示登录阻塞；实际尝试更新 `lastCheckedAt`，不因阻塞重复累加采集失败次数。拟新增 `AuthRunStatus=AUTH_REQUIRED | AUTH_UNVERIFIED`，正式检查响应允许原 RunStatus 或 AuthRunStatus；手工更新 / 撤销另记 `AUTH_UPDATED / AUTH_REVOKED`，来源 `AUTH_CONTROL`，不作为内容结果提醒。结果 feed 包含鉴权失败，排除授权控制操作。

成功验证后导出轮换状态，不限于 TEXT 提取成功：即使提取规则错误，仍应保留已确认有效的新 Cookie。身份凭证、授权范围或验证规则手工改变，以及撤销操作增加 `revision`，单纯改名不增加；每次浏览器工作持有该修订号，保存状态和提交采集结果都校验它。保留状态而改变 revision 时须按新 AAD 重新加密。自动轮换只增加 `state_version`，身份互斥避免旧上下文覆盖新状态。规则预览仍不写任务基线、快照或变化，但允许更新已验证的会话轮换状态。

## 5. 保护范围

### 管理入口与密钥

拟新增 `ADMIN_TOKEN` 和 `AUTH_MASTER_KEY`：前者至少 32 个随机字节，后者为 Base64 编码的 32 字节 AES 密钥。两项都配置才启用登录身份。只有从未启用过身份保护的旧库，才可在不配置时保留 v0.1 公开页面模式；不能创建或使用登录身份。

首次启用后持久化 `app_security.auth_required=1`，删除全部身份也不清除此标记。此后缺少任一配置时拒绝不安全启动，不能把已有私人历史重新暴露为公开 API。格式有效但密钥无法解密或密文损坏时，保留管理鉴权、将相关身份置为不可用并给出脱敏错误；不删除数据或匿名采集。首轮不提供关闭此保护的开关。

启用身份能力后，管理会话保护所有业务 API、缩略图、快照和更新流；仅最小 health、会话登录及受配对码限权的采集接口例外。网页输入 ADMIN_TOKEN 换取 HttpOnly、SameSite=Strict、最长 12 小时的会话 Cookie；HTTPS 使用 Secure。Token 不存 localStorage，不进 URL；退出立即撤销，重启后重新解锁。保留 Host / Origin 校验，写请求增加会话 CSRF 令牌，登录接口独立限流。

### 凭证与网络

- AES-256-GCM 加密状态，每次独立随机 nonce，认证附加数据绑定身份 ID 与 revision；数据库仅保存密文、nonce、tag。主密钥放 `.env`，不存数据库。错密钥和篡改状态必须拒绝使用，不能降级。
- 登录 URL、验证 URL、任务 URL、重定向和弹窗主机均需精确批准；SSO 域由用户显式补充，不自动信任整个父域。Cookie 父域需单独批准，并按公共后缀规则拒绝 `.com`、`.co.uk` 等范围。拟使用 `tldts`，启用私有后缀识别，避免把多租户共享域当作同一站点。
- 无关域的 Cookie / origins 明确拒绝并报告脱敏域名，不静默混入凭证。保持服务端 Chromium 沙箱、公共地址检查和 Docker 出口隔离；本机助手同样复用应用层公共地址 / 域范围校验，不开放远程调试端口。
- 助手不写 storageState 明文文件，不共享持久化浏览器目录；结束时关闭 Context / 浏览器并清理临时目录。凭证值、上传体、配对码、管理员 Token 不进入应用日志、异常、URL 或浏览器持久化存储。
- 状态加密不等于全部数据加密：采集正文、变化和 JPEG 仍含私人内容。数据目录按最小权限保存，所有读取鉴权，私密响应 no-store；备份与主密钥分开保管。本版不承诺磁盘整体加密或透明主密钥轮换。

### 通知隐私

带身份任务默认只发送“某任务有变化，请打开 PageSentinel 查看”，不向 ntfy 发送目标 URL、正文、条目标题或截图。用户可按任务明确开启完整变化推送；公开任务保留原行为。页面 / 浏览器系统通知对带身份任务也默认摘要，管理页面内查看完整证据。

登录失效提醒仅包含任务名和需重新登录的状态，按阻塞周期去重。拟新增持久化 `auth_alerts`，复用当前通知 Worker 的发送与退避机制；不将鉴权失败伪装成 TEXT / LIST 变化事件。主动清除登录态只记录操作；恢复后清理过时待发提醒，新一轮自动失效可以再次提醒；任务删除清理其未发送项。

## 6. 拟定数据与接口

以下是新契约，不是当前已存在的 API。

| 位置                    | 拟新增内容                                                                                                                                      |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `auth_profiles`         | id、名称、来源、登录 / 验证 URL、批准主机、成功 CSS / 登录前缀、状态、revision、state_version、密文 / nonce / tag、验证时间、脱敏失败码、时间戳 |
| `monitors`              | 可空 `auth_profile_id`（删除 RESTRICT）、成功 CSS 覆写、`auth_blocked_code`、阻塞时间、通知内容策略；旧行无身份                                 |
| `check_runs` / 共享类型 | 增加 `AuthRunStatus` 与 `AUTH_UPDATED / AUTH_REVOKED` 控制记录、`AUTH_CONTROL` 来源；监控 lastStatus 保留原采集枚举                             |
| `auth_alerts`           | 任务 / 身份 / 阻塞周期、待发 / 已发、重试次数 / 下次时间、创建时间；唯一约束防止重复提醒                                                        |
| `app_security`          | 单例 `auth_required` 标记；首次启用身份保护后持久保留，防止降为无鉴权模式                                                                       |
| 内存采集会话            | 会话 ID、配对码摘要、身份 / 修订号、状态、到期和心跳；不存原始登录态                                                                            |

| 方法                 | 拟定路径（前缀 `/api`）                                  | 语义                                                           |
| -------------------- | -------------------------------------------------------- | -------------------------------------------------------------- |
| POST / DELETE / GET  | `/admin/session`                                         | 解锁 / 注销 / 会话与 CSRF 信息                                 |
| GET / POST           | `/auth-profiles`                                         | 元数据列表 / 创建空身份                                        |
| GET / PATCH / DELETE | `/auth-profiles/:id`                                     | 元数据 / 编辑规则 / 无绑定时删除                               |
| POST                 | `/auth-profiles/:id/import`                              | Cookie / storageState 规范化、服务端验证、原子保存             |
| POST                 | `/auth-profiles/:id/verify`、`/auth-profiles/:id/revoke` | 验证保存身份 / 清除状态并阻塞任务                              |
| POST                 | `/auth-profiles/:id/captures`                            | 创建一次性登录会话，仅此响应带配对码                           |
| GET / DELETE         | `/auth-captures/:id`                                     | 管理端查询 / 取消                                              |
| POST                 | `/auth-captures/:id/save`                                | 管理端请求助手保存                                             |
| POST                 | `/auth-captures/pair`                                    | 助手消费配对码，换取仅限该会话的令牌                           |
| GET / POST / DELETE  | `/auth-captures/:id/helper`                              | 助手轮询 / 提交状态 / 取消，按 HTTP 方法区分，仅限助手令牌权限 |

Cookie、storageState 和 raw header 统一归一为内部 `StorageState`。管理侧只接触 `AuthProfileSummary`；`AuthContext` 是服务端内部对象，不进入共享前端响应。`MonitorInput.authProfileId` 可空，身份变更参与现有规则修订与基线重建。

## 7. 兼容、升级与发布

增量升级 SQLite，保留已有任务、快照、已见 Key、变化与 ntfy 待发。原有公开任务默认无身份；启用管理入口鉴权是启用登录身份后的显式部署变化，不静默改变现有纯公开模式。

Docker 继续只运行无头采集；本机助手按需安装完整 Chromium，不把有界面浏览器 / VNC 塞进运行镜像。新增运行依赖须加入 `docker/runtime-dependencies.mjs`，保持镜像裁剪有效。新环境变量须在 Compose 显式透传；不得只更新 `.env.example`。

升级前备份完整数据及独立密钥。若需回滚 v0.1，先停 v0.2，恢复升级前数据库和兼容配置，再切换旧镜像；**不能只降级镜像继续使用带登录任务的 v0.2 数据库**，否则旧逻辑可能匿名访问并破坏基线。

## 8. 评审需要确认的选择

1. 接受“网页创建会话 + 运行本机助手打开专用窗口”，Docker 首轮不做远程桌面。
2. 接受 Cookie JSON / 请求头文本及 storageState 三种输入格式；暂不支持 Netscape / sessionStorage。
3. 接受启用身份能力时的单管理员解锁、独立加密密钥与私密通知默认摘要。
4. 确认第一个真实验收站点；验收由用户操作登录 / MFA，不将凭证发到对话或仓库。站点未选前可完成受控回归，不能据此宣称真实站点已兼容。

## 参考与证据

- [Playwright Authentication](https://playwright.dev/docs/auth)：隔离 Context、状态复用及 sessionStorage 边界。
