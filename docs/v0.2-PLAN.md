# v0.2 登录监控实施计划

> **待评审，禁止据此自动开始开发。** 设计与本计划经维护者确认后，再按任务顺序实施；本轮仅整理文档。执行者须同时阅读[设计方案](v0.2-DESIGN.md)，不能将本文拟定接口当成已有实现。

**目标**：交付专用窗口登录、Cookie / storageState 导入两条完整路径，让现有 TEXT / LIST 安全复用登录态，并在失效后保留证据、提醒和恢复。

**架构**：现有 Vue / Fastify / SQLite / Chromium 主链路保持。新增登录身份和本机助手，统一状态归一化、服务端验证、加密持久化与身份锁；Docker 仍只运行无头采集。

**技术**：沿用项目锁定的 Node / TypeScript / Playwright；加密使用 `node:crypto`。新增 `tldts` 处理公共 / 私有后缀，实施时核实兼容版本并精确锁定；不引入 Redis、远程桌面或账号平台。

## 全局约束

- 保持 v0.1 任务、历史、快照、已见 Key、通知、独立开关和原 API 语义；无身份任务原样运行。
- 只实现两种已指定方式；成功标记、域范围、加密、管理鉴权、失效恢复及私密通知属于这两条路径的必要组成。
- 2 MiB 状态请求体、500 Cookie、20 批准主机；10 分钟一次性配对；全局最多 2 个捕获会话、同身份最多 1 个；助手轮询 2 秒，连续失联 30 秒终止。
- 每次正式采集 / 预览 / 验证使用独立 Context；同身份串行，先取得身份锁，再占全局采集槽。
- 不提交代码，不读取或写入其他项目；不在日志、响应或测试快照中输出凭证；不拿真实用户凭证当 fixture。
- 先完成阶段编码，再执行对应验证；有失败时只修复本阶段问题。复用本轮已通过的无关验证，不为汇报重复执行。
- 所有任务当前均未执行；勾选需有相应代码和证据。真实站点由用户操作登录 / MFA，不能用受控站点结果代替真实兼容性。

## 风险复核重点

| 场景                                                   | 必须实现的结果                                   | 所属任务 |
| ------------------------------------------------------ | ------------------------------------------------ | -------- |
| 曾启用登录能力后，移除环境密钥或删光身份               | 不能重新暴露私人历史；鉴权要求不能随身份数量消失 | 1、7     |
| 旧采集进行中，用户换账号或撤销身份                     | 旧结果和旧 Cookie 都不能覆盖新授权               | 3、4     |
| HTTP 200 的登录页、单路径 403、CSS 改版                | 拒绝污染基线，又不误停整个账号                   | 3、4     |
| 手机访问服务 / Docker 无 GUI、SSO 越界、助手关闭或失联 | 清楚说明本机助手要求，安全失败并清理会话         | 5、6     |
| 私人正文、URL、Cookie 进入 ntfy 或共享响应             | 默认仅发送脱敏状态，原文推送必须用户选择         | 1、4、6  |
