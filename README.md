# PageSentinel · 页面哨兵

Track what matters. 只追踪真正关心的网页变化。

本地优先、自部署的公开网页监控工具。支持 TEXT 区域文本变化和 LIST 历史未见条目检测；通过真实 Chromium 提取内容，保存变化证据，并以 ntfy 推送通知。实现范围见 [v0.1 项目规划](docs/PageSentinel_项目规划_v0.1/README.md)。

## 本地运行

建议 Node.js 24 LTS（最低 22.12）及 npm。首次安装：

```sh
npm ci
npm run browser:install
cp .env.example .env
npm run dev
```

打开 <http://127.0.0.1:5173>。Vite 将 `/api` 代理到本机 3000 端口。Linux 首次安装浏览器时可以使用 `npx playwright install --with-deps chromium` 安装系统依赖。

构建后由同一个 Fastify 进程提供前端和 API：

```sh
npm run build
npm start
```

打开 <http://127.0.0.1:3000>。SQLite 默认保存于 `data/pagesentinel.sqlite`，关闭网页不会停止后端；退出 Node 服务后自动检查才会停止。请只运行一个实例访问同一数据库。备份时先停止服务，再备份整个数据目录，包含可能存在的 WAL 文件。

## 创建监控

1. 点击“新建监控”，填写名称、公开 HTTP(S) 地址和 CSS 选择器。
2. TEXT 必须恰好选中一个区域；可按行填写要排除的子元素选择器。
3. LIST 选择器匹配每个条目。标题、链接选择器相对于条目查找；留空时使用条目文本及其唯一链接，条目本身是 `<a>` 时可直接使用。必须有非空标题、唯一且有效的详情链接。
4. 点击“测试规则”，确认真实提取结果。测试不会保存任务或推进正式基线。
5. 保存后立即采集，首次成功只建立基线。之后自动检查或手动“立即检查”使用同一流程。
6. 在详情先查看当前成功采集内容与页面缩略图，再查看区域变化、列表新增条目、执行来源、采集摘要、精确到秒的时间、耗时、失败原因和通知状态。区域变化先独立展示新增内容，可一键复制；完整对比支持默认“统一查看”和左右“并排查看”，保留各自的行号与修改对齐。仅删除时会明确提示没有新增内容。

检查间隔使用自定义时分：小时 0—24，分钟 0—60，合计至少 1 分钟、最多 1500 分钟；服务端在每次间隔上随机增加或减少 5—10 秒，界面显示实际下次时间。列表上的“刷新全部”会强制采集全部任务（包括已暂停任务），每项完成后重置下一次调度时间；批次期间禁止重复启动。各任务独立控制自动检查，关闭后仍可手动检查。开启和关闭操作会保存到任务执行记录，包含秒级时间和操作来源，不改变采集基线或产生变化通知。

LIST 只根据规范化详情 URL 的 SHA-256 识别新增；保留查询参数、去除片段。重排、旧条目回归、同链接标题变更不会产生新增事件。TEXT 只压缩空白，不自动删除数字和日期。

URL、模式或当前模式的提取规则修改会重建基线；名称、间隔、启用状态修改会保留基线。历史变化和执行记录仍保留。暂停只停止后续自动调度，已开始的检查和手动检查仍可完成。删除任务会级联删除其所有数据和待发通知。

## 通知与配置

配置项见 [.env.example](.env.example)。`NTFY_URL` 是完整主题 URL，例如你自己的 `https://ntfy.example.com/unguessable-topic`；`NTFY_TOKEN` 可选。订阅同一个主题即可接收变化通知。

未配置 ntfy 时，变化事件仍持久化为待发送；配置并重启后会发送积压事件。发送失败指数退避，最大重试间隔 6 小时；短消息直接发送，长消息按 UTF-8 字节限制为摘要，完整证据在详情中。通知采用至少一次投递，发送成功后状态落库前若进程崩溃，允许重复推送。首次基线、提取失败、无变化均不发送 ntfy 通知。

右上角消息中心展示最近监控结果。“页面消息提醒”和“浏览器系统通知”独立开关，偏好保存在当前浏览器；初次打开只读取历史，后续检查才触发新提醒。浏览器通知需显式授权，适用于 HTTPS 或 localhost 安全上下文；macOS 还需允许对应浏览器的系统通知。页面打开时轮询接收，关闭后没有 Web Push；需要持续后台推送时使用 ntfy。测试通知发送最近一条真实监控结果。

| 配置                      | 默认值               | 说明                                             |
| ------------------------- | -------------------- | ------------------------------------------------ |
| `HOST` / `PORT`           | `127.0.0.1` / `3000` | API 和生产前端监听                               |
| `PUBLIC_HOST`             | 未设置               | 反向代理访问域名，不含协议和端口；用于 Host 校验 |
| `DATA_DIR`                | `./data`             | SQLite 持久化目录                                |
| `CHECK_CONCURRENCY`       | `2`                  | 自动、手动和预览共享上限，范围 1—4               |
| `NAVIGATION_TIMEOUT_MS`   | `20000`              | 页面导航超时                                     |
| `TARGET_TIMEOUT_MS`       | `10000`              | 等待目标元素超时                                 |
| `STABILITY_TIMEOUT_MS`    | `10000`              | 稳定采样总时长                                   |
| `SAMPLE_INTERVAL_MS`      | `1000`               | 连续两次采样相同视为稳定                         |
| `NTFY_URL` / `NTFY_TOKEN` | 未设置               | 单个通知目标和可选鉴权                           |

调度每秒扫描到期且启用的任务，同站采集至少间隔 2 秒；失败按连续次数退避，最大检查间隔 24 小时。重启仅处理到期任务，不补跑停机期间每一个周期。

## Docker 单容器

```sh
docker compose up -d --build
```

打开 <http://127.0.0.1:3000>。项目的 `./data` 目录映射到容器的 `/app/data`，用于保存 SQLite 数据；该目录已排除 Git 和构建上下文。修改 `.env` 后运行 `docker compose up -d`，停止使用 `docker compose down`。

更新源码或 `.env` 后，一键更新当前本地部署：

```sh
./deploy.sh
```

脚本支持 macOS / Linux，可从任意目录通过脚本完整路径执行，只依赖 Docker、Compose v2 和 curl，无需在宿主机手动运行 npm 打包。它复用 Docker 构建缓存，先构建再替换容器，最后检查 `http://127.0.0.1:3000/api/health`。构建失败不会替换旧服务；容器启动或健康检查失败会返回非零退出码并给出排查命令。替换期间会短暂中断访问，当前 `.env` 重新加载，项目 `data` 目录和原有监控记录保留；脚本不删除数据、执行 Git 操作或清理镜像。

从旧版命名卷迁移时，先停止服务以保证数据库一致，再将旧容器 `/app/data` 下的完整内容（包括可能存在的 WAL 文件）复制到项目 `data` 目录，最后重建容器。迁移确认前保留旧卷。

镜像使用多阶段构建，最终阶段只保留服务器运行依赖、当前平台的 SQLite 原生绑定、编译产物和 Chromium；前端库及构建工具不会进入运行镜像。

应用与 Chromium 以 `node` 用户运行，Chromium 沙箱保持开启。入口脚本短暂使用网络管理权限配置出口规则后放弃权限；Compose 的自定义 seccomp 策略基于 [Playwright 官方策略](https://github.com/microsoft/playwright/blob/main/utils/docker/seccomp_profile.json)，额外允许沙箱用户命名空间内所需的 `chroot`。配置依据 [Playwright Docker 文档](https://playwright.dev/docs/docker)。

默认仅向宿主机回环地址发布端口。容器禁止主动连接本机、内网、保留 IPv4 段及 IPv6；仅放行配置的 DNS 解析器原始 53 端口及已建立的连接。该限制也覆盖浏览器重定向、子资源和 DNS 重绑定。内网地址的 ntfy 同样不可达，应使用公开 HTTPS 的自部署通知地址。Docker 需要支持 iptables、conntrack 和非特权用户命名空间；入口配置失败时会停止启动，不会关闭沙箱或跳过出口限制。

本地直接启动仅有应用层公共地址校验，无法消除 DNS 重绑定与浏览器自身网络行为的所有风险；访问不可信网页优先使用默认容器。不要将无鉴权服务直接暴露到公网。需要远程访问时，在带鉴权的反向代理后配置 `PUBLIC_HOST`。

## API

接口前缀 `/api`，成功直接返回 JSON；错误返回 `{ "code": "...", "message": "..." }`。时间为 Unix 毫秒。

| 方法                 | 路径                      | 行为                                               |
| -------------------- | ------------------------- | -------------------------------------------------- |
| GET                  | `/health`                 | 服务状态、是否配置 ntfy；不返回密钥                |
| GET / POST           | `/monitors`               | 列表 / 创建（201，后台立即建立基线）               |
| GET / PATCH / DELETE | `/monitors/:id`           | 详情 / 更新 / 删除（204）                          |
| POST                 | `/monitors/test`          | 真实测试未保存规则                                 |
| POST                 | `/monitors/:id/check`     | 等待本次正式检查结束，返回状态；重复检查返回 409   |
| GET                  | `/monitors/:id/events`    | 变化历史，包含可读 Diff 或本次新增条目             |
| GET                  | `/monitors/:id/checks`    | 执行记录，包含来源与采集摘要；旧记录标记为历史记录 |
| GET                  | `/settings`               | 读取全量刷新批次状态                               |
| POST                 | `/monitors/check-all`     | 202 接受全量强制刷新；重复批次返回 409             |
| GET                  | `/monitors/:id/current`   | 最近成功内容、采集时间与缩略图时间                 |
| GET                  | `/monitors/:id/thumbnail` | JPEG 页面缩略图；没有图时返回 404                  |
| GET                  | `/updates`                | 最近 20 条检查消息；`after` 游标分页读取后续结果   |

创建示例（示例域名和选择器需替换）：

```json
{
  "name": "软件更新日志",
  "url": "https://example.org/changelog",
  "mode": "TEXT",
  "selector": ".changelog-content",
  "ignoreSelectors": [".update-time"],
  "intervalMinutes": 30,
  "enabled": true
}
```

测试接口只接受规则字段：`url`、`mode`、`selector`、可选 `ignoreSelectors`、`titleSelector`、`linkSelector`。LIST 标题和链接选择器可以通过 PATCH 设为空字符串来清除。分页接口接受 `pageIndex`（从 1 开始）、`pageSize`（默认 20，最大 100），返回 `{ items, total, pageIndex, pageSize }`。正式检查结果可能是 `BASELINE`、`UNCHANGED`、`CHANGED`、`FAILED`；采集期间规则发生变化或任务被删除时返回 `{ discarded: true }`，旧结果不会写回。

## 验证

```sh
npm test
npm run build
```

测试使用受控静态正文、延迟 SPA、可变列表及本地 ntfy 接收端，真实运行 Chromium 和 SQLite，覆盖文档的六组回归。仅测试工厂显式注入本地地址白名单，生产入口不提供关闭公共地址校验的环境变量。

人工 UI 验收可运行 `npm run test:ui:serve`，使用内存数据库和命令输出的受控页面地址；先执行构建，打开 4173 端口。追加 `-- --seed` 可通过真实采集生成包含文本变化、列表新增、暂停、失败和仅删除变化的示例任务，示例仅存在于这个临时内存服务。该入口仅用于本机验收。

详细验证记录见 [开发进度](docs/开发进度.md)。一个月持续试运行和个人实际 ntfy 主题投递需在配置真实环境后观察；不会把受控接收端验证称为用户通知服务已经接通。
